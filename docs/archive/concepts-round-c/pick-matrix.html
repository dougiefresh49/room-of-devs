Round C · pick matrix · five concepts, one brief

Pick a base. Graft the rows.

Five designs were drawn against the same locked brief. This page exists so the choice can be made in plain text instead of five open tabs. Every row below is a decision the brief left open; every cell is a position plus what that position costs you. Rows where all five landed in the same place are marked as settled — skip them.

base: Settle Line; salience queue: Settle Line; cost readout: Work Item; concierge presence: Quiet Floor; dock: Settle Line; mobile: Sol · Ledger
01

The five, in the same shape

Same four fields each, so they are actually comparable. Read this block first; the matrix assumes it.

Opus

The Settle Line

Thesis
The scarce resource is your attention and the one audio floor, so the app is a vertical column where height means audibility — above the line you hear it, below it you can see it, below the second line it is only written down.
Primary object
The ticket, as a row. The live thread is a hatched sprig hanging under it that vanishes on settle.
Distinctive bet
One material rule — hatched is mortal, solid is settled — teaches #73's whole doctrine without a word of onboarding, and the same column renders on all three surfaces, merely cropped.
Fable

The Quiet Floor

Thesis
The room is working correctly when it is silent, so every surface is an attention ledger that makes silence legible and interruptions earned; work is text you glance at and the only faces belong to voices.
Primary object
The work item — but the primary axis is attention: layout is Needs you → Holding for a lull → Working → Settled today, and tracker state is demoted to a chip.
Distinctive bet
The held queue is a first-class group in the ledger with one drain button, "Brief me · one breath", which collapses N held items into one Gemini call and one synthesis.
Sol

Signal Desk · Ledger

Thesis
A quiet editorial control desk: durable work stays visible, speech is a scarce broadcast channel, and the owner sees only the decisions worth interrupting life for.
Primary object
The obligation — a durable work item plus the decision it may eventually require of you. Sessions and workers are never shown at all.
Distinctive bet
The dock is a broadcast valve: it shows the line being spoken and the speak-now / next-lull / log-only counts, so you can demote a whole event class from the periphery without opening the window.
Grok

Signal Desk · Tray

Thesis
The room earns silence, so the window should be about the short list of things that broke it — not about the inventory of work, which becomes wallpaper you stare at.
Primary object
The attention tray: rebuilt every snapshot from spine gate events, keyed to attention debt rather than to any context window. Work is demoted to a "hinterland" side column.
Distinctive bet
It refuses the work ledger as the main view — the only board to argue that a full ticket catalog recreates the failure at a slower cadence — and gives the three surfaces three different shapes.
Candidate A

Work Item

Thesis
The UI has exactly three jobs — talk to the concierge cheaply, see what is true underneath without asking, and receive/question/keep artifacts — plus one new control, the salience surface, which is the reason the round exists.
Primary object
The work item — ticket + thread + activity + artifacts + spend. The concierge is chrome, not an object.
Distinctive bet
Cost is a first-class readout: a four-row mono meter (rules · flash · borrowed · synthesis) plus an escalation log keyed to the config rule that fired.

Written before the round and demoted to a competing entry. It is prose, not a board — so it has no drawn surfaces, no material language, and no anti-goal self-check. Where a row below reads "no answer", that is why.

Name collision, resolved. Two entries independently landed on Signal Desk. Throughout this page they are always Sol · Ledger (obligation rows + a decision desk; the dock is a broadcast valve) and Grok · Tray (an attention tray with work pushed to a hinterland column). They are not variants of each other — they disagree about the primary object.

sharp fork

1 · Primary object

The noun everything else hangs off. The brief said the work item is the strong default and must be beaten explicitly — two entries tried.

Opus · Settle Line

The ticket, as a row. The thread is a hatched sprig under it that disappears on settle and leaves a solid green settle-note.

a ticketless one-off never gets a row at all — quick asks live only in the floor line and the log tail, and vanish with them.

Fable · Quiet Floor

The work item, with attention as the primary axis. Accepts the brief's default and sharpens it rather than beating it.

the tracker's actual state geometry is never visible at a glance; GitHub is the escape hatch for anything shaped like planning.

Sol · Ledger

The obligation — work item plus the decision it may require. Sessions and workers are never rendered.

work with no pending decision is structurally second-class, so "grinding for three hours, fine" is the state this board serves worst.

Grok · Tray

The attention tray — things that broke silence, rebuilt each snapshot. Tickets exist, in a hinterland column.

browsing all work becomes a deliberate detour, and the screen you stare at all day is empty by design — which is either the thesis or a void.

Candidate A · Work Item

The work item, argued from mortality: a card keyed to a context window dies at /clear.

it never answers the tray or obligation framings, because it predates them — its argument is only against session cards.

fork

2 · Main-window shape / IA

What is on screen at rest, and how many panes it takes. The panel is ~940px wide in practice, which is the constraint that decides this.

Opus · Settle Line

One column + a detail pane. Column runs floor → speak line → ledger → log line → composer, top to bottom, in that order always.

one region carries salience, work and log at once, so the column gets long and the detail pane is the only place with any density.

Fable · Quiet Floor

Ledger + inspector, with the concierge as a desk bar across the bottom. Ledger is grouped by what the room wants from you.

two dense columns plus a desk bar leaves nothing spare; a long Needs-you group pushes Working off screen entirely.

Sol · Ledger

Three panes: nav rail (Attention / In motion / Quiet / Artifacts / Cost / Rules), editorial ledger, decision desk.

three panes at 940px is exactly the density problem Candidate A named, and the rail spends a whole column on six links.

Grok · Tray

Booth rail + tray + hinterland, with a persistent salience policy bar as the footer.

two of three columns are secondary, so most of the window is chrome around a region that is empty when things go well.

Candidate A · Work Item

Concierge rail (260px) + work board; item detail replaces the board rather than adding a third column.

you cannot see the board and an item at once, and a quarter of the window is permanently a face plus two readouts.

sharp fork

3 · Should the three surfaces share a shape?

The brief asked this directly. It is the row with the largest build-cost consequence: one component tree versus three IAs.

Opus · Settle Line

Hard yes. All three render the same ordered column; the dock is the top of it, the phone is it full-bleed, the panel adds a detail pane.

the desktop gives up density a wide screen could afford, and the phone inherits desktop ordering it did not ask for.

Fable · Quiet Floor

Yes for panel and phone (same ledger, folded); the dock is its own thing — a one-line pager.

the phone could have been a purer remote control; instead it carries the desk's grouping and its scroll.

Sol · Ledger

Explicit no — "they do not share a shape because they do not share a job": read / govern / decide.

three IAs to design, build, and keep from drifting — the most expensive answer on this row, and the hardest to keep consistent across two JS realms.

Grok · Tray

Explicit no, three shapes, and it lists "shared shape across surfaces" as something to cut from today.

same bill as Sol — it calls it "more design surface area" itself — for a product with one developer.

Candidate A · Work Item

Same objects, different arrangement: glance (dock) → work (window) → away (phone); nothing exists on one surface that is invented there.

the middle path buys neither a single component tree nor a phone tuned to the phone; parity has to be maintained by discipline.

sharp fork

4 · The concierge's physical presence

The widest spread on the board — from zero avatars in the main window to the largest avatar the product has ever had. Taste-critical and structural at once.

Opus · Settle Line

Zero avatars in the window. The speak line is the presence — it lights and its rule animates. Exactly one avatar, in the dock.

the biggest screen loses all the warmth you paid ElevenLabs and an art pipeline for; buys a work surface with no face watching you.

Fable · Quiet Floor

One 38px face in a bottom desk bar with a caption line, PTT, typed input and attach — the whole conversational surface is one strip.

its own decisions table admits the risk: "Mikey can feel like a widget."

Sol · Ledger

An abstract broadcast lens, salient only in the dock; the main window has no persistent presence at all.

the least character of the five — a lens is not a cast, and the persona work becomes almost purely audio.

Grok · Tray

A booth rail: small avatar, vertical name, status lamp; expands into a caption only while speaking.

spends a permanent column on something that is a lamp for most of the day.

Candidate A · Work Item

A 260px rail holding the one avatar "at the largest size it has ever had", with the salience queue and spend meter beneath it.

a face watches you while you work, and the rail must earn a quarter of a 940px window every day — not just on the days it speaks.

5 · How work reads — grouping, sort, density

How you tell "waiting on me" from "grinding" from "done" without reading words. All five refuse a kanban; they differ on what the sort key is.

Opus · Settle Line

One list "sorted by what it wants". Blue gutter is the only chromatic alarm; amber grinding, grey watching, green settled. Ceremony is a 3-bar gauge, spend a hairline.

four states is all you get — anything finer has to live in the detail pane, by explicit rule.

Fable · Quiet Floor

Grouped by attention state — Needs you / Holding / Working / Settled today — with tracker state demoted to a chip and an amber pulse for grinding.

group membership changes under you as states flip, and it is the only grouping that does not match what GitHub shows.

Sol · Ledger

Numbered editorial rows — ordinal, state dot, one line of "what must be decided", ceremony gauge. Agent-state colors retired; orange means you owe a decision.

an ordinal implies a queue position that nothing actually maintains, and rows are tall, so six is a screenful.

Grok · Tray

A dense hinterland stack (id, title, gear chip) plus a density strip of state dots — deliberately not readable at a glance.

answers "what is the state of #75" worst of the five, on purpose; you go to the tracker instead.

Candidate A · Work Item

Grouped by state, with a stable sort that never reorders under the pointer — a state change restyles the row in place. Row shows gear, spend, artifact count, room chip.

the densest row of the five, and the rule that rows never move means the list is briefly lying about its own order.

sharp fork

6 · The salience surface — the held queue

"Killing the true filter is the reason this round exists." The policy is settled (row 7). What is genuinely open is whether the queue of unspoken things is a browsable place or deliberately not.

Opus · Settle Line

A pill welded to the speak line ("3 held for a lull"), not a region. Held items coalesce into one spoken sentence at the next lull (90s of no audio and no press). Past ~6 the pill turns amber — "that is a policy bug".

you cannot skim what is pending without a click; buys a surface whose correct state is empty and that never invites queue-gardening, and cuts synthesis N→1.

Fable · Quiet Floor

A permanent "Holding for a lull" group in the ledger, each row naming the rule that held it, with "Brief me · one breath" as the drain (1 Gemini + 1 ElevenLabs for N items).

pending items occupy real estate every day even though the right number is zero; the honesty of naming the holding rule per row is the payoff.

Sol · Ledger

Counts, in the dock valve: speak now / next lull / log only, with "ROOM QUIET · 0 waiting · 3 events logged silently" as the resting mark.

you can see how many are held but not what they are — the weakest read of the queue's contents, traded for the strongest peripheral control of it.

Grok · Tray

The tray is the surface, but only for things that already broke silence; queued classes appear as chips on a policy bar, not as a list.

the "waiting for a lull" bucket has no home at all — the one bucket the round was called to design gets a chip.

Candidate A · Work Item

A full SalienceQueue list: per entry Play / Read (expand as text, free, no TTS — the default cheap path) / Dismiss, plus "Play all (N)" with a duration estimate and "Hold the room".

the most machinery and the most invitation to manage a queue that should be empty; but "Read" is the only free drain path anyone designed, and it deserves grafting onto whatever wins.

settled · open 7 · The salience policy — how speak/queue/silent is expressed All five: a checked-in table of event class → speak / queue / log, edited by a human, never a model's judgment. Same defaults. Nothing to decide.
Unanimous, including the default values. Gates speak (blocker, needs-feedback, plan-review, settled/failed); milestones and routine progress queue for a lull; tool chatter and subagent-finish are silent — today's announce-leak inverted into a visible default rule. All five make it config, versioned and diffable, and all five say explicitly that no model gets to rate its own importance. Only the doorway differs, and it is cosmetic: Opus makes the speak line itself the button (click the rule, get the table); Fable a settings sheet with two rows pinned to log-only in v1; Grok a three-column policy strip pinned to the desk footer with an "edit policy" link; Sol a nav item; Candidate A a table reachable from the queue header, scoped per room. Take whichever the base gives you.

8 · The cost readout

Number, meter, texture, ledger, or ambient — and specifically whether "today's burn" is visible in chrome at all. Opus is the outlier here and knows it.

Opus · Settle Line

Ambient. A hairline per row, explicit chips only for escalations, each naming the rule that fired. No day total in chrome — it lives in settings.

you cannot glance at what today cost, which in a repo whose stated top priority is credit efficiency is the one place this board's austerity actually bites.

Fable · Quiet Floor

A header total ("today $1.12 billed · $0.09 est") plus a full cost.jsonl ledger, one line per LLM and synthesis call.

a number in the chrome nags; its own answer is that ambient displays cannot be audited, and spend here is a product concern, not telemetry.

Sol · Ledger

Per-obligation block on the decision desk — BILLED · ESTIMATE · FRONTIER BORROWS — plus the day total as a nav-rail figure.

spend is scoped to whatever is selected, so "what is today costing me" is always one click and one selection away.

Grok · Tray

A hinterland block: big today figure, a bar with an escalation blip, and a three-line log.

the blip is the closest thing on any board to cost-as-decoration; least auditable of the four numeric treatments.

Candidate A · Work Item

A four-row mono SpendMeter — rules / flash / borrowed / synthesis — plus an EscalationLog with the matched rule, tier, model, duration, cost and the first line of the ask.

permanent rail space; but it is the only readout that separates ElevenLabs characters — this repo's actual cash cost — from LLM spend, which is the distinction the credit rules are written around.

settled · open 9 · Escalation legibility & estimate honesty All five: every escalation names the config rule that fired, and estimates are visually distinct from billed truth. Only the notation differs.
Unanimous, and it matches architecture doc 05 exactly. No board lets a model declare its own difficulty; every escalation prints the rule (rule: plan-review → frontier) beside its cost. Estimates never masquerade as billed: Opus hatches estimates and keeps billed rows solid; Fable sets billed in bold and estimates in grey italic and never sums them into one number; Sol splits BILLED from ESTIMATE as separate lines; Grok tags escalations in the log; Candidate A states the rule as copy ("where a figure is an estimate, the readout says so"). One sub-fork worth a sentence: only Candidate A adds a manual per-turn override — a "Think hard" toggle on the composer that forces the borrowed tier and writes an escalation row with rule: manual, visually distinct in the log. Opus explicitly refuses any "be smarter" control near the conversation. That is a real choice, but a one-line one.

10 · The dock — content and states

A non-activating NSPanel that must never steal focus. All five agree it has no text input. They disagree about how much authority it gets.

Opus · Settle Line

Four states (resting / wants you / speaking / voice checked out) and it promotes the top flagged row's most common action to one click — "approve #74" — plus hold-to-talk and hush.

the most useful dock and the most exposed: acting on work from a never-focusing panel is one careless build from writing tracker state from the periphery.

Fable · Quiet Floor

A one-line pager (~40px): the quiet line, plus exactly one urgent thing when one exists. "Speak it" / "brief me" / open. Never a list — two waiting things defers to the floor.

no per-thread action at all, so every real decision costs a window activation.

Sol · Ledger

A broadcast valve: the line being spoken with its source and billed cost, plus speak-now / next-lull / log-only counts you can demote from.

the only dock that edits policy from the periphery — powerful, and the easiest to change something important by accident on a panel with no focus.

Grok · Tray

Lamp + at most one signal + PTT + expand; a spotlight lifts above the pill while speaking; resting shows the word QUIET as a feature.

the least you can do from the dock of the five — safest against focus theft, weakest as a reason to keep the surface.

Candidate A · Work Item

Four states in priority order: speaking (caption + transport) / something waiting (Play it · Later) / mic open (whole strip inverts to light) / quiet ticker. Rejects type-through by name as a TCC subsystem.

"Play it / Later" is a salience action, not a work action — cheaper and safer than Opus's approve button, and correspondingly less reason to glance at it.

settled · open 12 · The artifact loop All five drew the same loop: a rendered file, version chips, Ask, and a named Keep. No canvas anywhere. Nothing to decide beyond where the card lives.
Unanimous, down to the mechanics. 19 · New backend required

The brief says a design needing no new backend beats an equally good one that does. Gathered from each board's own pricing — and the answer is that this row cannot decide anything.

All five need the same three things, and nothing else of consequence: (1) a salience router — an event-class policy file plus a held-queue state file, surfaced in PanelSnapshot; (2) a spine mirror — gh issue list plus the live state/* labels projected into the snapshot; (3) a cost rollup over the per-call log the interpreter already emits. All five reuse the existing hash-cached mermaid→SVG path for artifacts, and all five explicitly refuse timing capture, a seek engine, a canvas, a floor/turn system, and a database. Two of the three are already committed architecture work, not new bills. So price is not the discriminator the brief hoped it would be — pick on shape.
Opus · Settle Line

The only board with day estimates: ~1d salience policy + queue, ~2h lull detection, ~1d ticket projection, ~½d spend tail, ~½d artifacts. Adds a lull timer (90s no audio, no press) nobody else has, which coalesces N announcements into 1 — net cheaper than today.

it also declares a hard dependency: "if needs-feedback stays prose, the blue gutter is a lie" — the spine labels must land first.

Fable · Quiet Floor

Same three, priced as "small daemon module" each, plus the "Brief me" drain (1 Gemini + 1 ElevenLabs for N items) and an artifact registry. "Everything else on this board: $0 — pure client rendering of the snapshot."

no time figures, so "small" is doing some work; the drain is genuinely cheaper than today.

Sol · Ledger

Declares three items "no new backend" (ledger projection, PTT surfaces, concierge lens) and three "small" (salience policy snapshot, cost rollups, artifact metadata). The lightest declared bill.

it is lightest partly because it prices categories rather than work — the ledger projection it calls free is the same spine mirror others price as a day.

04

If you want to answer fast

Six questions. Answer these and the target is decided; everything else is either already unanimous or is a thing the mock will answer better than a board can.

The six that matter

In rough order of how much else they decide.

  1. Is the main window the work, or what broke the silence? Work ledger in the middle (Settle Line · Quiet Floor · Sol Ledger · Work Item) versus an attention tray with work in a side column (Grok Tray). Every other row inherits from this. Grok's argument — that a full ticket catalog becomes wallpaper — is the one real challenge to the brief's default, so decide it deliberately.
  2. Is there a face in the main window at all? None, presence is the speak line (Settle Line) · a 38px desk bar (Quiet Floor) · a booth rail lamp (Grok Tray) · an abstract lens, dock only (Sol Ledger) · a 260px rail with the biggest avatar yet (Work Item). This is the row where the product's warmth is spent or saved, and it cannot be deferred — it sets the layout.
  3. Is the held queue a browsable list, or deliberately not? A pill that expands and coalesces to one spoken sentence (Settle Line) · a permanent group with a one-breath drain (Quiet Floor) · a full list with per-item Play / Read / Dismiss (Work Item) · counts only (Sol Ledger) · effectively nowhere (Grok Tray). This is the reason the round exists; it is also where "the correct number is zero" collides with "let me see what's pending."
  4. Do the three surfaces share a shape? Yes, one column cropped three ways (Settle Line) · mostly (Quiet Floor, Work Item) · explicitly no, three jobs three shapes (Sol Ledger, Grok Tray). This is the largest build-cost lever on the page for a one-developer product.
  5. Is today's spend visible in chrome, and is TTS broken out from LLM? Ambient hairlines with no day total in chrome (Settle Line) · a header total plus a call ledger (Quiet Floor) · per-obligation with a rail figure (Sol Ledger) · a figure with an escalation blip (Grok Tray) · a four-row meter separating synthesis from the three brain tiers (Work Item). Given that ElevenLabs is the cash cost this repo guards, Work Item's split is the only one aimed at the actual risk.
  6. Can the dock take a work action, or only a salience action? Approve the top flagged item in one click (Settle Line) · demote an event class from the valve (Sol Ledger) · play it / later (Work Item) · speak it / brief me (Quiet Floor) · essentially nothing (Grok Tray). This decides whether the dock is worth keeping as a surface at all.
Safely deferrable to the mock — because they are already unanimous, or because a rendered screen answers them better than a static board can: the salience policy table (row 7) and its defaults · escalation and estimate notation (row 9) · the artifact loop (row 12) · rooms and attribution (row 17) · ceremony mutability (row 14) · palette and material (row 15) · copy doctrine (row 16) · mobile detail below the shape question (row 11) · the cut list beyond the shared core (row 18).

One item that is deferrable but must not be forgotten: Candidate A's open question — does mobile Talk absorb live mode? No other entry addresses it, Opus quietly assumes yes by killing CallView as a mode, and it is the only decision here that deletes something already shipped and in use.
Opinion — mine, not a finding

I would take the Settle Line as the base: it is the only entry whose material rule teaches the architecture rather than describing it, its bill is the only one priced in days, and it is the only board where the salience surface is the thing you stare at all day instead of a settings screen you visit. Then graft three things. From Work Item, the four-row spend meter and the free Read action on held items — Opus's refusal of a day total is the one place its austerity costs real value, and Work Item is the only readout that separates ElevenLabs cash from LLM spend. From Quiet Floor, the billed-bold / estimate-italic type rule and the "settles → summary on the ticket" button copy. From Grok, take the warning rather than the design: its point that a ticket catalog becomes wallpaper is correct, but the fix is Opus's sort-by-what-it-wants plus a blue-gutter-only alarm, not demoting work to a side column and staring at an empty tray. Keep Opus's pill over Work Item's full queue list — the correct number really is zero — and answer the live-mode question early, because it is the only decision on this page that deletes something you already use.
