The call — where it lives

The hangar is the fourth rung of the zoom ladder, above the plot: HANGAR ↔ PLOT ↔ RAIL ↔ NODE, hard cuts, no tween — the ladder stays a contract, not a camera. Plot and below are per-room; the hangar is the only surface where all rooms exist at once. It is not a new window and not a mode: same console shell, one cut up. It lives on fleet.zoom, never on a room's ViewMode — a fleet fact does not belong on a per-room object.

The ladder finally has an exit GRAFT ▸ OPUS · A4

Fable specified ⌘0–⌘n addressing but no way out. ESC climbs one rung — NODE ▸ RAIL ▸ PLOT ▸ HANGAR — and coupling into a berth is a hard cut back down, landing on that room's rail. One keydown handler completes the ladder contract, and the prototype has no keyboard model at all today, so this is net-new capability rather than a rework.

The call — bays, not a starmap

Spatial position carries no meaning for rooms — a starmap invents distance where none exists (§2.6 in spirit: don't render invented data). Berth numbers are stable addresses (⌘1–⌘4 switch, ⌘0 for the hangar), the floor bus on the left is the one-global-audio-floor rule made physical, and the traffic strip IS the shared salience queue with room attribution — cross-room urgency reads without opening a single room. The starmap callout on the plot retires. Rejected from the donor set: a second hazard-striped audio bar along the bottom (the 26px vertical bus already carries holder + queue), a separate SKIFF LANE (a whole second grammar for 0–2 items), and sol's orbital switchyard (the exact invented-distance framing this callout kills).

Every traffic row carries the speak gate GRAFT ▸ OPUS · A3

Fable's rows carry clear-% and floor state but nothing that ties them to salience.threshold, which already exists in types.ts. With belowGate printed per row the strip answers the actual operator question — "what is Mikey allowed to interrupt me about?" — because the red rows are exactly that set. The gate is computed once, fleet-wide, not stitched from per-room thresholds; that is the whole reason the shared queue exists. Cost: one boolean. Note what stays static: rows do not scroll — grok's marquee FLOOR QUEUE ticker was rejected for animating on its own account.

A scratch berth says where it was born GRAFT ▸ OPUS · A5

A scratch berth is dashed, spineless, and un-numbered. No plan glyph, no gear tag, no standing cast — Mikey narrates it, and when its craft settles the berth dissolves; nothing bolts on. One-offs are usually born inside a room ("draw me the auth flow"), so the plate now carries parentRoomId and prints FROM R-DEVS. Without it a scratch berth reads as an orphan project. One optional field.

The bench's output is a file you can read GRAFT ▸ OPUS · A1

Fable showed a manifest preview — a static illustration of what would be written. Opus's version is live-bound: every control edits the pane, and the pane header prints the real path. That kills new-project anxiety ("what did that wizard just configure?") and matches the architecture exactly, because rooms arrive as configuration. Two consequences fall out for free: a second entrance — hand-edit the file, no bench needed — and a free undo, git checkout. Cost: bind one JSON renderer to draft state.

What was NOT taken: opus's "ceremony is one knob, not two flows" (BARE detent = skiff). It conflates room durability — is a manifest checked in — with per-thread gear default. Fable is right to fork first and dial second; the fork answers "is this a real project", the dial answers "how much process per piece of work".

Each dial prints its consequence in the unit that bites GRAFT ▸ OPUS · A2

The dials are the only place a person can accidentally make a project expensive, and cost honesty is already THE CORE's whole thread. Fable prints each dial's architectural home (plan card / faceplate / turn chip) — keep that, and add one consequence line under the active detent: ceremony in extra turns per piece of work, voice in per-character billing, brain tier in dollars per turn. One line of copy per detent, applied at the moment the cost is chosen instead of the moment it is discovered.

Rooms are config, not architecture

The commission writes a file — nothing else. The daemon watches the manifests directory the same way it watches queue files today; a new manifest = a new berth on the next snapshot. Decommissioning is deleting a file (with the spine left intact in the tracker). The one-off path never writes at all: it files a scratch manifest in memory, and the berth dissolves when the craft settles.

The call — a catalog, not a storybook

No knob panels, no prop playgrounds. Each instrument gets a spec plate — the states it ships, stamped provenance, stock lamp, where-used pins, tolerances, path — because the question this page answers is "what do we have and what is it made of," not "what could this render." The states row IS the API surface. Every state rack is a set of fixed fixtures shown at once; a catalog animates only what the component itself animates, at its true rate. No gauge climbs, no simulated data.

Four stamp classes, not three GRAFT ▸ OPUS · B1

Fable's three classes — FORGED IN-HOUSE (steel), RADIX ▸ * (amber), CVA · NO RADIX (violet) — have no home for components the audit explicitly calls "not a registry concept". A taxonomy with a hole mis-stamps real parts, so a fourth class is added: LIB ▸ <name> (green) for third-party non-shadcn bases — Markdown (react-markdown + rehype-sanitize) and toast (sonner). Where a registry component was considered and rejected, the plate prints the rejection verbatim; a parts book that only records what you chose gets re-litigated every six months.

The stock lamp makes the catalog a maintenance instrument GRAFT ▸ OPUS · B2

Fable's dead-stock signal is binary. Three states is the fact you actually want: green ≥2 consumers, amber exactly one — one deletion from dead — and red zero. button and SessionDial are amber today. It costs nothing: it's the existing Led primitive. Honest side effect worth printing in the crib copy: after this build all three dead primitives have a consumer, so their lamps go red → amber — fragile, not clean. Show that rather than claiming a clean sheet.

The crib lives at /crib on 5180, and the counts come from a file GRAFT ▸ OPUS · B6

It ships beside /console and /field on the prototype's own dev server rather than the gallery's port 5179 — it reuses the existing path-sniff and avoids a second server. packages/ui/gallery/ is superseded: leave it in place with a pointer in its README until the crib lands, then it's a deletion candidate. Cut from the fable board: the hardcoded "33 INSTRUMENTS · 3 DEAD STOCK" counters — every count on this surface renders from the generated crib-manifest.ts, never from prose.

The call — where it lives, and why it isn't a rung

A SCHEMATIC keycap in the console header (and a control-deck trigger) opens it as a full-bleed layer — route /map in the prototype. Not a rung on the zoom ladder: the ladder is operational magnification of live work; the schematic is the service door you open when you've forgotten why a gauge exists. It renders no live data, so it can never lie about the room — it's the one screen allowed to be a document. Dropped from the donor set: opus's /plate naming (fable's /map matches the other lanes and reads better in a keycap) and opus's live LEDs on stratum I — a lamp showing whether a surface is currently rendering would make the map read live data and forfeit the "it can never lie" property.

Part numbers on every housing — and shift-click deep links GRAFT ▸ OPUS · C1

The strongest single idea in the donor set. Every console and field housing carries a stencilled part number (S-01…S-19 console, F-01…F-06 field, M-01… machine, R-01… rules) — and shift-clicking any housing opens /map with that part already selected. It makes the console its own index and answers "why is that thing there?" from where you asked it. Fable listed it as deferred; it is promoted to its own build phase, because inserting <PartNo/> touches every console and field housing file and therefore must run last.

The plate shows its own holes GRAFT ▸ OPUS · C3

"A map that only shows finished parts quietly lies about the machine." The prose doc ends with a "Not yet designed" section; the plate ends with red rivets in the middle column. Fable's map marks The Hangar ◂ NEW but has no home for known gaps. Rivet 1 (all-projects view) ships stamped FILLED · ROUND D — it goes amber and joins the plate. Rivet 2 (THE CORE and FIELD · GAUGES telling one spend story two ways) stays red. The gaps list becomes a UI state instead of a maintenance chore.
