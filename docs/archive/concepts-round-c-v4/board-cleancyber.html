BLACK // GLASS

A dark instrument, not a dashboard. One voice behind machined glass; the work suspended on a spine of light; every thread's only score is how far it is from needing you. FIG · 10

What I chose, what I rejected, what it costs

ChoseOverTradeoff
Light as the only status system Color-coded badges, status columns Needs discipline — one warm accent, ever; if everything glows, nothing does.
Salience ring with a physical threshold A notifications list / filter settings page The interrupt policy becomes one draggable object — but it needs a real daemon-side score.
Spine as a vertical light column Timeline, kanban, tree view Reads at a glance top-to-bottom (shipped → active → queued); poor at showing 30 plans. We never have 30.
Cartoon faces inside machined faceplates Silhouettes or abstract orbs to match the refs The tension IS the product — premium housing tells you the toy is load-bearing.
Terminal nodes expand in place A drill-down detail page Depth on demand keeps one surface; very long feeds need an internal scroll, not more page.
Phone = face + ring + one sentence Porting any desktop surface Owner is still deciding what the phone is; thin now beats wrong now.
Map radius = the salience score, reused A force-directed graph with its own layout physics One number drives the instrument, the dock, AND the map — but the map can't show relationships salience doesn't encode (tethers to plans carry that).
Question options as controls in the card Reading options aloud and parsing free speech Click/number/say-the-number all hit the same AskUserQuestion hook — cheap and honest; nuanced answers still need free-form voice, which stays available.
Threads wear their sleeve's face A persona column, or renaming threads after personas One glance answers "who is this" — but it means the face art appears at three scales (rail, card, map), so the frames must stay cheap (they're CSS background swaps).
Dials live in their objects A settings page with three dropdowns Gear on the card, voice on the faceplate, brain in the routing table — discoverable in place, but changing a default still needs one config home behind it.

New engineering, honestly: the salience score itself — a daemon-side number per thread (distance-from-needing-you, from tracker state + held events), plus a user threshold in config.json that gates speech. Everything else here renders from the PanelSnapshot the daemon already broadcasts. The tap-in harness already proved the state labels this ring would feed on.

FIG · 11

What I'd cut to rein it in

The rotating / animated salience ring
Expensive: live-updating SVG instrument with a draggable threshold handle, thread dots animating along radii as scores change.
Cheap version: a static arc with dots re-placed on each snapshot; threshold set by a plain slider in settings. The concept survives — “distance from needing you” — without the observatory.
Per-thread live terminal tail in the expander
Expensive: streaming tmux capture into every open node, throttled, with scrollback.
Cheap version: last-8-lines snapshot on expand (live-tail.ts already reads transcripts), refreshed with the snapshot rev. Feels 80% as alive.
Blueprint schematics inside spine slabs
Expensive: rendering each plan's real step-graph as a wiring diagram per slab.
Cheap version: only the ACTIVE slab gets a schematic, generated once per plan version as a static SVG artifact Mikey renders — versioned files, which is already our rule for things he shows you.
The living map (FIG 02)
Expensive: continuous drift animation, tether curves to plan structures, a second room's spine, faces at map scale, pinch-zoom continuity into room and node views.
Cheap version: a static polar plot re-placed on each snapshot — the salience score already gives the radius, angle hashed from thread id, plans as a plain list on the right edge. No zoom continuity: the map is a fourth view you switch to. The owner's sentence survives: everything in flight, at a glance, like space.
Voice-answerable option controls (FIG 04)
Expensive: matching arbitrary speech ("the first one, but in a subdir") to options with confirmation flows.
Cheap version: click and number keys only; voice stays free-form reply-to-thread, which already exists. Saying "one" is a Stage-2 interpreter verb when it comes — the card doesn't change.
The birth flow as ceremony (FIG 06)
Expensive: animated three-stage intake with verb matching UI and a newborn card materializing on the rail and map simultaneously.
Cheap version: Mikey says "filed, Karai's on it" and the thread simply exists in the next snapshot. The verb shelf is just `ls` over the spine's verbs dir rendered as chips — that part is nearly free and worth keeping.
Dial faces as instruments (FIG 07)
Expensive: three bespoke SVG rotary instruments with needle animation.
Cheap version: the homes already carry the value as text (gear on the card, tag on the faceplate, tier line under spend). The dials figure is explanation, not UI — it can be a doc page instead of panel chrome.
