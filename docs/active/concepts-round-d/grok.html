DESIGN NOTE · WHERE IT LIVES

Hangar is a fourth zoom rung, not a sibling nav item next to console/plot. The existing contract (hard cuts, no pinch tween) extends upward. From console you hit HANGAR via a faceplate keycap or “zoom out past plot.” Switching rooms = hard cut into that berth’s RAIL — the spine you see is always per-project. One-offs render as dashed berths with a NO SPINE stub and a red MORTAL tag; full-ceremony berths show a real spine stub with dock LEDs.

DESIGN NOTE · CROSS-ROOM SALIENCE

The FLOOR QUEUE is the dock-strip’s multi-room brother: one shared salience queue with room attribution on every item. You never open a quiet room to learn a loud one is screaming. The speaking lamp is exclusive — lighting a second berth’s lamp extinguishes the first (audio floor law from arch 05).

WIRE NEEDS · EXTENDS types.ts

ViewMode gains "hangar". Today’s RoomState remains one berth’s interior. Salience queue attribution is the load-bearing new field — without it the hangar is mute.

DESIGN NOTE · BROWSING MODEL

Spec-sheet layout, not a grid of pretty cards. Left rail is the bin index (stencil section headers = shop aisles). Selecting a part loads the sheet: live demos across states, provenance chip, usage chips, path. Search filters the index. Category rails are hard cuts (same zoom-ladder grammar). The existing gallery at packages/ui/gallery/ becomes this surface — evolve, don’t orphan. Provenance data comes from docs/reference/shadcn-audit.md.

DESIGN NOTE · RIG PARTS STAY CUSTOM

All 13 RIG primitives stamped FULLY CUSTOM on purpose. Registry analogues (card/badge/progress/chart) would not survive the chamfer restyle. Leave them alone — the catalog’s job for RIG parts is documentation + state coverage, not migration.

DESIGN NOTE · WHERE IT LIVES

Dedicated route /map inside the prototype control-deck family — reachable from the deck drawer and a SCHEMATIC keycap on the console faceplate. Not a zoom-out gesture (that’s Hangar’s job). Diagram is ~60% of the surface; inspector is the other 40%. Links are amber conduits (same visual language as craft→plan stems), not Bezier spaghetti. Dim-unrelated on select keeps the board readable at 20+ nodes.

DESIGN NOTE · DIAGRAM VS INSPECTOR

The canvas is a locator, not a tutorial. Depth lives in the inspector — the same four answers as the text architecture map (what / why / arch tie / wire). That means the schematic can stay sparse and still replace the wall of prose for day-to-day “why is that there?” questions. New hangar nodes (surface + HangarState wire) are stamped NEW so Round D’s additions read as part of the same machine.

WIRE NEEDS · SCHEMATIC ITSELF

The schematic is a static authored graph in the prototype (prototype/src/map/graph.ts) — nodes + edges + inspector copy. It does not need daemon fields. It documents the wishlist in types.ts. When a surface lights up a wire node that doesn’t exist yet, the inspector tags it WISHLIST so the gap stays honest.
